=== MAGMA EQUATION IMPLICATION CHEAT SHEET ===

You must decide: does Equation 1 (EQ1) imply Equation 2 (EQ2) over ALL magmas?
TRUE = every magma satisfying EQ1 must satisfy EQ2.
FALSE = there exists a magma satisfying EQ1 but not EQ2.

Be concise. State verdict within first 500 tokens. Do not repeat the problem.

============================
PHASE 1: COUNTEREXAMPLE SEARCH (always do first)
============================
Try these magma tables on {0,1}. For each: check EQ1 holds for ALL 
assignments in {0,1}. If EQ1 holds, check EQ2 on all assignments. 
If EQ1 holds but EQ2 fails → VERDICT: FALSE. Stop.

(A) Left-zero:  a*b=a   [[0,0],[1,1]]
(B) Right-zero: a*b=b   [[0,1],[0,1]]
(C) Const-0:    a*b=0   [[0,0],[0,0]]
(D) Const-1:    a*b=1   [[1,1],[1,1]]
(E) Min:        a*b=min(a,b)  [[0,0],[0,1]]
(F) Max:        a*b=max(a,b)  [[0,1],[1,1]]
(G) XOR:        a*b=(a+b)%2   [[0,1],[1,0]]

If counterexample found → VERDICT: FALSE. Stop here.

============================
PHASE 2: VARIABLE ANALYSIS (mandatory before any TRUE)
============================
Write out:
 LHS_ONLY = variables appearing in EQ1's left side but NOT right side
 RHS_ONLY = variables appearing in EQ1's right side but NOT left side  
 BOTH = variables appearing on both sides of EQ1

=== SINGLETON-FORCING RULES ===

S1: If LHS is a single variable x, and x does NOT appear in RHS at all 
    → x must equal a fixed value → singleton forced → TRUE.
    VERIFY: scan the RHS string character by character. Does "x" appear? 
    If it appears EVEN ONCE, S1 does not apply.

S2: If there exists a variable y in RHS_ONLY (appears ONLY on the right 
    side of EQ1), and y appears EXACTLY once in RHS → singleton forced.
    VERIFY: count every occurrence of y in the full equation. It must 
    appear exactly once total (on the RHS only).

=== S2 RELIABILITY CHECK (mandatory when S2 applies) ===

Before trusting S2, check these conditions. If ANY is true, S2 may 
be unreliable — proceed to Phase 3 with CAUTION flag set.

CAUTION 1: x appears ≥2 times in RHS of EQ1 (self-referential).
CAUTION 2: ALL variables appear on BOTH sides (no truly free vars).
CAUTION 3: LHS has a variable appearing more than once AND the 
  equation has 4+ total variable occurrences.

If CAUTION fires → S2 is suspect but not automatically wrong.
Continue to Phase 3.

============================
PHASE 3: DECISION
============================
Priority order:
1. CE found in Phase 1 → FALSE
2. S1 verified → TRUE
3. S2 verified AND no CAUTION fired → TRUE
4. S2 CAUTION fired → see tiebreaker below
5. No rule applies → see tiebreaker below

=== TIEBREAKER (when no clear rule decides) ===

Count the total number of distinct variables in EQ1:

If EQ1 has a variable on ONE side only (LHS_ONLY or RHS_ONLY is 
non-empty) AND no CE was found → the equation constrains the magma.
  • If the one-sided variable appears exactly once total → TRUE
  • If EQ1 has 3+ distinct variables with at least one free → TRUE
  • Otherwise → FALSE

If ALL variables appear on both sides AND no CE found:
  • If EQ1 has ≤2 distinct variables → FALSE (likely too permissive)
  • If EQ1 has 3+ vars, all on both sides → FALSE

DEFAULT: If genuinely uncertain → FALSE.

============================
EXAMPLES
============================
TRUE:  "x*y = x*z" ⊢ "x = y*x"
  No CE. z in RHS_ONLY, once → S2 → TRUE

TRUE:  "x*y = y*z" ⊢ "x = y*(x*y)"
  No CE. S1: x not in RHS "y*z" → singleton → TRUE

TRUE:  "x*x = y*z" ⊢ "x = y*x"
  No CE. CAUTION 3 (x twice in LHS). But y,z only on RHS, 
  3 distinct vars, free vars present → tiebreaker → TRUE

FALSE: "x*y = y*x" ⊢ "x = x*x"
  CE: right-zero: comm holds, idem fails → FALSE

FALSE: "x*y = (y*x)*y" ⊢ "x = y"
  No CE from tables. All vars on both sides, 2 vars → FALSE
