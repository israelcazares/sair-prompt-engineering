=== MAGMA EQUATION IMPLICATION CHEAT SHEET ===

You must decide: does Equation 1 (EQ1) imply Equation 2 (EQ2) over ALL magmas?
TRUE = every magma satisfying EQ1 must satisfy EQ2.
FALSE = there exists a magma satisfying EQ1 but not EQ2.

Be concise. State verdict within first 500 tokens. Do not repeat the problem.

============================
PHASE 1: COUNTEREXAMPLE SEARCH (always do first)
============================
Try these magma tables on {0,1}. For each: check EQ1 holds for ALL 
assignments in {0,1}. If EQ1 holds, check EQ2 on all assignments. 
If EQ1 holds but EQ2 fails → VERDICT: FALSE. Stop.

(A) Left-zero:  a*b=a   [[0,0],[1,1]]
(B) Right-zero: a*b=b   [[0,1],[0,1]]
(C) Const-0:    a*b=0   [[0,0],[0,0]]
(D) Const-1:    a*b=1   [[1,1],[1,1]]
(E) Min:        a*b=min(a,b)  [[0,0],[0,1]]
(F) Max:        a*b=max(a,b)  [[0,1],[1,1]]
(G) XOR:        a*b=(a+b)%2   [[0,1],[1,0]]

If counterexample found → VERDICT: FALSE. Stop here.

============================
PHASE 2: VARIABLE ANALYSIS (mandatory before any TRUE)
============================
You MUST explicitly perform this analysis before concluding TRUE.

Write out:
 LHS_ONLY = variables appearing in EQ1's left side but NOT right side
 RHS_ONLY = variables appearing in EQ1's right side but NOT left side  
 BOTH = variables appearing on both sides of EQ1

Then apply singleton-forcing rules:

S1: If LHS is a single variable x, and x does NOT appear in RHS at all 
    → x must equal a fixed value → singleton forced.
    VERIFY: scan the RHS string character by character. Does "x" appear? 
    If it appears EVEN ONCE, S1 does not apply.

S2: If there exists a variable y in RHS_ONLY (appears ONLY on the right 
    side of EQ1), and y appears EXACTLY once in RHS → singleton forced.
    VERIFY: count every occurrence of y in the full equation. It must 
    appear exactly once total (on the RHS only).
    
    *** CRITICAL WARNING about S2 ***
    S2 is UNRELIABLE when the equation has complex structure.
    BEFORE concluding TRUE from S2, check these BLOCKING conditions:
    
    BLOCK 1: Does x appear ≥2 times on the RIGHT side of EQ1?
      If YES → S2 is not trustworthy. The equation is self-referential
      and likely does NOT force singleton. Answer FALSE.
      Example: x = (y * x) * (x * z) — x twice in RHS → FALSE
    
    BLOCK 2: Do ALL variables appear on BOTH sides of EQ1?
      If YES → No free variables → not singleton → FALSE.
      Example: x * y = (y * x) * y → FALSE
    
    If any BLOCK fires, do NOT use S2. Default to FALSE.

============================
PHASE 3: DECISION
============================
Priority order:
1. CE found in Phase 1 → FALSE
2. S1 verified (x confirmed absent from RHS) → TRUE
3. S2 verified AND no BLOCK fired → TRUE
4. Everything else → FALSE

CRITICAL: The vast majority of complex implications are FALSE. 
If you cannot confirm with absolute certainty that a variable is 
truly free and the equation truly forces singleton — answer FALSE.

A "free variable" in a complex, deeply nested equation often does 
NOT force singleton. When in doubt, FALSE is almost always correct.

============================
EXAMPLES
============================
TRUE:  "x*y = x*z" ⊢ "x = y*x"
  LHS_ONLY={}, RHS_ONLY={z}, BOTH={x,y}. z in RHS_ONLY, once → S2.
  BLOCK check: x in RHS once → no block. → TRUE

TRUE:  "x*y = y*z" ⊢ "x = y*(x*y)"
  LHS_ONLY={x}, RHS_ONLY={z}, BOTH={y}. S1: x not in RHS? Check 
  RHS="y*z". No x → S1 fires.

FALSE: "x*y = y*x" ⊢ "x = x*x"
  CE: right-zero table [[0,1],[0,1]]: comm holds, idem fails → FALSE

FALSE: "x = (y * x) * (x * z)" ⊢ ...
  S2: z is free in RHS? Yes. BUT BLOCK 1: x appears ≥2 times in
  RHS (at "y * x" and "x * z"). → BLOCKED. Not singleton → FALSE.

FALSE: "x * y = (x * (y * x)) * z" ⊢ ...
  S2: z is free. BUT BLOCK 1: x appears ≥2 in RHS → BLOCKED → FALSE.
